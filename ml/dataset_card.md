# 데이터셋 카드 — travel-mission-photos

미션 2단계 사진 인증 모델 학습용 이미지 분류 데이터셋.

## 클래스

`labels.json` 참조. `투어 / 맛집 / 체험 / 쇼핑` + `무효` 5개.

## 목표 규모

| 클래스 | 목표 장수 | 비고 |
| --- | --- | --- |
| 투어 | 800~1200 | 랜드마크·전망·거리, 국내 위주 |
| 맛집 | 800~1200 | 음식·식당 내부·메뉴판 |
| 체험 | 500~800 | 공방·액티비티·전통 체험 (수집 난이도 높음) |
| 쇼핑 | 500~800 | 상점·시장·상품 진열 |
| 무효 | 1000~1500 | 셀카·스크린샷·무관 실내·흐린 사진 (음성 표본) |

## 수집 출처

- **공개 데이터셋** (`ml/data/fetch_public.py`, 비스트리밍):
  - 맛집: **Food-101** (`ethz/food101`) validation 스플릿 — 101개 음식 클래스 전부에서 고르게
  - 투어/체험/쇼핑: **Places365 validation 셋** (`dpdl-benchmark/Places365-Validation`, 365 scene × 100장).
    라벨 인덱스는 `ml/data/places365_categories.txt` 로 이름화하고 `place_classes.py` 로 카테고리 매핑
    (매핑: 투어 107 · 체험 53 · 쇼핑 28 scene). scene 당 상한 100장.
  - 스트리밍 모드는 클래스 정렬 때문에 몇 개 scene 으로 편중돼 쓰지 않는다.
- **크라우드소싱**(권장, 미적용): 동기·지인이 실제 미션을 수행하며 촬영한 사진 (도메인 일치도 가장 높음).
  `raw/<카테고리>/<장소이름>__001.jpg` 로 넣으면 같은 파이프라인으로 합쳐진다.
- **무효 표본** (`ml/data/make_negatives.py`): 합성 스크린샷 + 카테고리 이미지 열화(하드 네거티브) +
  `collected_invalid/` 직접 수집분. 얼굴이 크게 나온 사진은 최소화하고 공개 시 제외/블러.

## 분할

- train / validation / test = 70 / 15 / 15
- **분할은 촬영 장소(또는 원본 출처) 단위로 묶어서** 나눈다. 같은 장소 사진이
  train 과 test 에 동시에 들어가면 성능이 부풀려진다.
- 클래스 불균형은 학습 시 `class_weight` 또는 오버샘플링으로 보정한다.

## 포맷

HuggingFace `datasets` `imagefolder` 규칙:

```
travel-mission-photos/
├── train/
│   ├── 투어/ *.jpg
│   ├── 맛집/ *.jpg
│   ├── 체험/ *.jpg
│   ├── 쇼핑/ *.jpg
│   └── 무효/ *.jpg
├── validation/ ...
└── test/ ...
```

HF Hub 비공개 데이터셋으로 업로드 후 노트북에서 `load_dataset("<user>/travel-mission-photos")`.

## 라벨링 주의

- 음식이 찍혔지만 미션이 "쇼핑"이면 → 그 사진은 학습에서 "맛집"으로 라벨한다. (모델은 사진 내용만 보고 분류하고, 미션 카테고리와의 대조는 앱의 `PhotoVerification` 이 한다.)
- 애매한 사진(예: 식당이 있는 시장 거리)은 제외하거나 다수결 라벨링한다.
